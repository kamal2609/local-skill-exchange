# Phase 9 — Plan 09-02: Security Hardening & Automated Audit (Wave 2)

## 1. Goal
Harden the application against common OWASP web vulnerabilities (NoSQL injection, Clickjacking, MIME sniffing, Brute Force attacks) and implement an automated security audit script (`backend/test/securityAudit.js`).

## 2. Deliverables
1. **NoSQL Injection Sanitization Middleware (`backend/src/middleware/sanitize.js`):**
   - Recursively inspects `req.body`, `req.query`, and `req.params`.
   - Strips any keys starting with `$` or containing `.` to prevent MongoDB operator injection (e.g. `{"$gt": ""}`).

2. **Enhanced Security Headers & Rate Limiting (`backend/src/app.js`):**
   - Configure Helmet with custom Content Security Policy (CSP) permitting Three.js WebGL rendering, inline SVGs, and external image CDNs (Unsplash).
   - Dedicated authentication rate limiter for `/api/auth/*` (15 requests per 15 minutes per IP) to prevent password brute-forcing.
   - Global API rate limiter for `/api/*` (100 requests per 15 minutes per IP).
   - Mount sanitization middleware before route handling.

3. **Automated Security Audit Suite (`backend/test/securityAudit.js`):**
   - Verify security HTTP response headers (`X-Content-Type-Options`, `X-Frame-Options`, `Content-Security-Policy`).
   - Verify NoSQL injection sanitization strips operator keys without crashing the server.
   - Verify authentication route rate limiting headers and 429 response when threshold is exceeded.
   - Verify CORS headers only accept configured origins.
   - Verify invalid JWT signatures are rejected with HTTP 401.

## 3. Acceptance Criteria
- [ ] NoSQL injection payloads are stripped cleanly from incoming request data.
- [ ] Helmet headers are present in all HTTP responses.
- [ ] Auth rate limiter enforces 15 requests per 15-minute window.
- [ ] `node backend/test/securityAudit.js` executes and passes 100% of security checks.
