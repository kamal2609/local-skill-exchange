# Phase 2 — Plan 02-02: User Profiles & Public Directory API (Wave 2)

## 1. Goal
Implement user profile retrieval, update endpoints, public user directories, and profile picture/skills management.

## 2. Deliverables
1. `backend/src/validators/userValidators.js`:
   - `updateProfileSchema`: name, bio, city, preferredLearningMode (`ONLINE`, `IN_PERSON`, `HYBRID`), languages, skillsOffered, skillsWanted, profilePicture.
2. `backend/src/controllers/userController.js`:
   - `getProfile`: Retrieves current authenticated user's profile with populated skills.
   - `updateProfile`: Allows authenticated users to update their personal details, bio, city, learning preferences, and skills offered/wanted.
   - `getUsers`: Public directory with pagination (`page`, `limit`), search query, role filter, city filter, and sorting.
   - `getUserById`: Public profile view for any user by their MongoDB ObjectId or username, populating offered and wanted skills.
3. `backend/src/routes/users.js`:
   - `GET /api/users/profile` (Protected)
   - `PUT /api/users/profile` (Protected with Zod validation)
   - `GET /api/users` (Public)
   - `GET /api/users/:id` (Public)
4. Mount `/api/users` in `backend/src/app.js`.

## 3. Acceptance Criteria
- [ ] Authenticated user can view and update their profile.
- [ ] Sensitive fields (`passwordHash`, `passwordResetToken`, `creditsBalance`, `role`) cannot be modified via `PUT /api/users/profile`.
- [ ] Public user endpoint returns community members with sanitized fields.
- [ ] Invalid user ID returns HTTP 404.
