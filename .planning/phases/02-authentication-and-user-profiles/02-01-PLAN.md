# Phase 2 — Plan 02-01: Backend Authentication API & RBAC Middleware (Wave 1)

## 1. Goal
Implement secure, production-grade JWT authentication, bcrypt password hashing, input validation schemas with Zod, role-based authorization middleware, and password reset endpoints.

## 2. Deliverables
1. `backend/src/utils/generateToken.js`: JWT signing helper with `JWT_SECRET` and 7-day expiration.
2. `backend/src/middleware/auth.js`:
   - `protect`: extracts Bearer token, decodes JWT, queries `User.findById(decoded.id)`, attaches to `req.user`.
   - `authorize(...roles)`: RBAC middleware ensuring user possesses one of the allowed roles (`LEARNER`, `PROVIDER`, `ADMIN`).
3. `backend/src/validators/authValidators.js`:
   - `registerSchema`: name (min 2), username (alphanumeric/dot/hyphen, 3-30 chars), email (valid email), password (min 6 chars), city, bio, role.
   - `loginSchema`: identifier (email or username), password.
   - `forgotPasswordSchema`: email.
   - `resetPasswordSchema`: token, password (min 6 chars).
4. `backend/src/controllers/authController.js`:
   - `register`: Validates uniqueness of email/username, hashes password, saves User with 3.0 credits balance, records `WELCOME_BONUS` transaction in `CreditTransaction`, and returns token + sanitized user.
   - `login`: Supports logging in via email or username, verifies password using `user.matchPassword()`, returns token + user.
   - `getMe`: Returns authenticated user with latest balance and profile.
   - `forgotPassword`: Generates secure crypto token, hashes and stores expiry in DB, returns token & reset URL in response.
   - `resetPassword`: Validates token & expiry, hashes new password, clears reset fields, returns new JWT + user.
5. `backend/src/routes/auth.js`: Mounts all auth endpoints and validation middleware.
6. Mount `/api/auth` in `backend/src/app.js`.

## 3. Acceptance Criteria
- [ ] Registration rejects invalid inputs with specific Zod validation errors.
- [ ] Duplicate email or username returns HTTP 409 conflict.
- [ ] Registration creates `User` document and `CreditTransaction` document with `WELCOME_BONUS` of 3.0 credits.
- [ ] Login returns HTTP 200 with JWT and user object when credentials match.
- [ ] Invalid credentials return HTTP 401 Unauthorized.
- [ ] `GET /api/auth/me` without Bearer token returns HTTP 401; with valid token returns current user.
- [ ] `authorize('ADMIN')` denies access to `LEARNER` or `PROVIDER` with HTTP 403.
- [ ] Password reset token generation and verification works with crypto hashes.
