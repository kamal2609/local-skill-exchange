# Phase 7 — Plan 07-01: Direct Messaging & Real-Time Notification APIs (Wave 1)

## 1. Goal
Implement the backend direct messaging system and notification center in `backend/src/controllers/messageController.js`, `backend/src/controllers/notificationController.js`, and their respective routes, enabling 1-on-1 conversations and alerts.

## 2. Deliverables
1. **`backend/src/validators/communicationValidators.js`:**
   - Zod schemas for sending messages, creating conversations, and marking notifications as read.
2. **`backend/src/controllers/messageController.js` & `backend/src/routes/conversations.js`:**
   - `getConversations`: `GET /api/conversations` (returns user's active threads populated with participants and last message).
   - `getOrCreateConversation`: `POST /api/conversations` (finds existing or creates new 1-on-1 thread with `recipientId`).
   - `getMessages`: `GET /api/conversations/:id/messages` (returns chronological message history).
   - `sendMessage`: `POST /api/conversations/:id/messages` (creates message, updates thread `lastMessage`, and creates a `MESSAGE` notification for recipient).
3. **`backend/src/controllers/notificationController.js` & `backend/src/routes/notifications.js`:**
   - `getNotifications`: `GET /api/notifications` (returns notifications with unread count).
   - `markAsRead`: `PUT /api/notifications/:id/read`.
   - `markAllAsRead`: `PUT /api/notifications/read-all`.
   - `createNotification` helper utility to create alerts during system events.
4. **Mount in `backend/src/app.js` and register in root discovery endpoint (`GET /api`).**

## 3. Acceptance Criteria
- [ ] Only conversation participants can view and send messages in a thread.
- [ ] Sending a message updates conversation's `lastMessage` timestamp and text.
- [ ] Notification endpoint returns unread count and notifications sorted by date descending.
- [ ] `PUT /api/notifications/read-all` updates all unread notifications to `isRead: true`.
- [ ] All routes protected with JWT authentication.
