# Phase 7 — Plan 07-02: Peer Review & Community Trust/Safety APIs (Wave 2)

## 1. Goal
Implement the peer review system and confidential trust & safety reporting mechanism in `backend/src/controllers/reviewController.js`, `backend/src/controllers/reportController.js`, and their respective routes, maintaining community reputation and safety.

## 2. Deliverables
1. **`backend/src/validators/communityValidators.js`:**
   - Zod schema for reviews: `sessionId`, `reviewedUserId`, `rating` (1 to 5), `comment`.
   - Zod schema for reports: `reportedUserId`, `reason`, `description`.
2. **`backend/src/controllers/reviewController.js` & `backend/src/routes/reviews.js`:**
   - `createReview`: `POST /api/reviews`
     - Validates session exists and status is `COMPLETED`.
     - Validates reviewer was a participant in the session.
     - Enforces uniqueness: only 1 review per session.
     - Recalculates provider's `averageRating` from all reviews and updates `User.averageRating`.
     - Creates `REVIEW_RECEIVED` notification for reviewed user.
   - `getUserReviews`: `GET /api/reviews/user/:userId` (public list of reviews for a user's profile).
3. **`backend/src/controllers/reportController.js` & `backend/src/routes/reports.js`:**
   - `createReport`: `POST /api/reports` (creates confidential report with status `PENDING`).
   - `getReports`: `GET /api/reports` (Admin-only list of reports with status filter).
   - `updateReportStatus`: `PUT /api/reports/:id` (Admin-only resolution).
4. **Mount in `backend/src/app.js` and register in root discovery (`GET /api`).**

## 3. Acceptance Criteria
- [ ] Reviewing a session before completion is blocked with HTTP 400.
- [ ] Submitting a review recalculates and updates `User.averageRating`.
- [ ] Duplicate reviews for the same session are rejected.
- [ ] Submitting a report queues the incident in `PENDING` status for moderation.
- [ ] `GET /api/reports` requires `ADMIN` role.
