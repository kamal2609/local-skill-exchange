# Phase 3 — Plan 03-03: Frontend Discovery Catalog & Posting UI (Wave 3)

## 1. Goal
Build responsive frontend pages for browsing the skill catalog, viewing teaching offers and learning requests, and posting new offers/requests with form validation.

## 2. Dependencies
- **Phase 3 Waves 1 & 2:** All backend API endpoints (`/api/skills`, `/api/offers`, `/api/requests`) must be mounted and functional.
- **Existing Frontend Infrastructure:**
  - `frontend/src/services/api.ts` — Axios client with JWT interceptor.
  - `frontend/src/context/AuthContext.tsx` — Authentication state.
  - `frontend/src/components/shared/ProtectedRoute.tsx` — Route guarding.
  - Tailwind CSS, Lucide React icons, Framer Motion.

## 3. Deliverables
1. **`frontend/src/pages/ExplorePage.tsx`** (replaces the Phase 1 placeholder at `/explore`):
   - **Tabbed Layout:** Two main tabs — "Skill Offers (Teach)" and "Learning Requests (Learn)".
   - **Category Filter Pills:** Horizontal scrollable row of category buttons (All, Technology, Design, Academic, Creative, Lifestyle, Other) with active state highlighting.
   - **Search Bar:** Text input with debounced search (300ms) filtering offers/requests by title, skill name, or description.
   - **Learning Mode Filter:** Buttons for All / Online / In-Person / Hybrid.
   - **Results Grid:** Responsive card grid (1 col mobile, 2 col tablet, 3 col desktop) displaying:
     - For Offers: Skill name, provider name & rating, experience level badge, mode badge, duration, neighborhood.
     - For Requests: Title, skill name, learner name, preferred difficulty, preferred mode, status badge.
   - **Pagination:** Page controls (Previous / Next / Page numbers) driven by backend `page` and `totalPages`.
   - **Empty State:** Friendly illustration/message when no results match.
2. **`frontend/src/pages/PostPage.tsx`** (replaces the Phase 1 placeholder at `/post`):
   - **Protected Route:** Only authenticated users can access.
   - **Mode Toggle:** "I want to Teach" (Create Offer) vs "I want to Learn" (Create Request).
   - **Teach Form (Create Offer):**
     - Skill selector: dropdown or searchable select populated from `GET /api/skills`. If the skill doesn't exist, show a "Create New Skill" inline mini-form.
     - Description textarea, experience level selector, learning mode pills, session duration slider (15-240 min), neighborhood input, teaching approach textarea.
     - Submit calls `POST /api/offers`.
   - **Learn Form (Create Request):**
     - Skill selector (same as above).
     - Title input, description textarea, learning objectives, preferred difficulty, preferred duration, preferred mode, preferred schedule, neighborhood.
     - Submit calls `POST /api/requests`.
   - **Validation:** React Hook Form + Zod schemas matching backend validation.
   - **Success Feedback:** Toast or inline success banner with link to view the new listing.
3. **`frontend/src/pages/OfferDetailPage.tsx`** (`/offers/:id`):
   - Displays full offer detail with populated skill info and provider profile card.
   - Shows provider's rating, completed sessions, and city.
   - "Request a Session" CTA button (placeholder for Phase 5).
4. **`frontend/src/pages/RequestDetailPage.tsx`** (`/requests/:id`):
   - Displays full request detail with populated skill info and learner profile card.
   - "Offer to Help" CTA button (placeholder for Phase 5).
5. **Update `frontend/src/App.tsx`:**
   - Replace placeholder `/explore` route with `<ExplorePage />`.
   - Replace placeholder `/post` route with `<ProtectedRoute><PostPage /></ProtectedRoute>`.
   - Add routes: `/offers/:id` → `<OfferDetailPage />`, `/requests/:id` → `<RequestDetailPage />`.
6. **Frontend production build must pass** (`npm run build --prefix frontend`) with zero TypeScript errors.

## 4. Acceptance Criteria
- [ ] `/explore` displays tabbed catalog with functional category filters, search, and pagination.
- [ ] Offer cards show skill name, provider name, experience level, learning mode, and duration.
- [ ] Request cards show title, skill name, learner name, difficulty, and status.
- [ ] `/post` is protected (redirects unauthenticated users to `/login`).
- [ ] Creating an offer via the Teach form sends correct payload to `POST /api/offers`.
- [ ] Creating a request via the Learn form sends correct payload to `POST /api/requests`.
- [ ] Offer detail page and request detail page load correctly with populated data.
- [ ] Production build succeeds without TypeScript or bundling errors.
