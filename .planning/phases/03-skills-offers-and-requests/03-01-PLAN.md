# Phase 3 — Plan 03-01: Skill Catalog Taxonomy API (Wave 1)

## 1. Goal
Implement a public, searchable Skill Catalog REST API that allows users to browse, filter, and propose new skills. The Skill model (`backend/src/models/Skill.js`) already exists from Phase 1 with categories, difficulty levels, tags, and text indexes.

## 2. Dependencies
- **Existing Model:** `backend/src/models/Skill.js` — Already has `name` (unique), `category` (enum), `description`, `difficulty`, `tags`, `icon`, `popularity`, `createdBy`, and a text index on `name`, `description`, `tags`.
- **Existing Middleware:** `backend/src/middleware/auth.js` (`protect`, `authorize`) and `backend/src/middleware/validate.js` from Phase 2.
- **Existing Seed Data:** `backend/src/seed/seed.js` already seeds 16 skills across 6 categories.

## 3. Deliverables
1. **`backend/src/validators/skillValidators.js`:**
   - `createSkillSchema`: Validates `name` (required, 2-100 chars), `category` (required, one of the 6 enum values), `description` (required, max 1000 chars), `difficulty` (optional enum), `tags` (optional array of strings), `icon` (optional string).
2. **`backend/src/controllers/skillController.js`:**
   - `getSkills`: Public. Returns paginated skill list with optional filters: `category`, `difficulty`, `search` (regex on name/description), `sort` (`popularity`, `name`, `createdAt`). Returns count of active offers per skill.
   - `getSkillById`: Public. Returns single skill detail with counts of active offers and open requests referencing it.
   - `createSkill`: Protected (any authenticated user). Prevents duplicate names (case-insensitive). Sets `createdBy` to `req.user._id`.
3. **`backend/src/routes/skills.js`:**
   - `GET /api/skills` — Public list with filters.
   - `GET /api/skills/:id` — Public detail.
   - `POST /api/skills` — Protected, validated.
4. **Mount `/api/skills` in `backend/src/app.js`.**

## 4. Acceptance Criteria
- [ ] `GET /api/skills` returns paginated list with category and difficulty filters working.
- [ ] `GET /api/skills` supports `search` query that matches against skill names and descriptions.
- [ ] `GET /api/skills/:id` returns skill detail with offer/request counts.
- [ ] `POST /api/skills` rejects invalid input with Zod validation errors (HTTP 400).
- [ ] `POST /api/skills` rejects duplicate skill names (HTTP 409).
- [ ] `POST /api/skills` without authentication returns HTTP 401.
- [ ] New skills are saved with `createdBy` set to the authenticated user.
