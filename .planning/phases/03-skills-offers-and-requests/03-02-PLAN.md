# Phase 3 — Plan 03-02: Skill Offers & Learning Requests API (Wave 2)

## 1. Goal
Implement full CRUD REST APIs for Skill Offers (teaching supply) and Learning Requests (learning demand), with ownership enforcement, status lifecycle management, pagination, and filtering.

## 2. Dependencies
- **Existing Models:**
  - `backend/src/models/SkillOffer.js` — Has `providerId`, `skillId`, `description`, `experienceLevel`, `teachingLanguage`, `learningMode`, `sessionDuration`, `neighborhood`, `teachingApproach`, `status` (ACTIVE/PAUSED/ARCHIVED), and a compound unique index on `(providerId, skillId)`.
  - `backend/src/models/LearningRequest.js` — Has `learnerId`, `skillId`, `title`, `description`, `learningObjectives`, `preferredDifficulty`, `preferredDuration`, `preferredMode`, `preferredSchedule`, `neighborhood`, `status` (OPEN → MATCHED → ACCEPTED → IN_PROGRESS → COMPLETED → CANCELLED → EXPIRED).
- **Phase 3 Wave 1:** Skill Catalog API must be mounted first (skills must exist to reference them).
- **Existing Middleware:** `protect`, `authorize`, `validate` from Phase 2.

## 3. Deliverables
1. **`backend/src/validators/offerValidators.js`:**
   - `createOfferSchema`: `skillId` (required, valid ObjectId), `description` (required, max 1000), `experienceLevel` (optional enum), `teachingLanguage` (optional), `learningMode` (optional enum), `sessionDuration` (optional, 15-240), `neighborhood` (optional), `teachingApproach` (optional, max 500).
   - `updateOfferSchema`: Same fields as create but all optional. Also allows `status` (ACTIVE/PAUSED).
2. **`backend/src/validators/requestValidators.js`:**
   - `createRequestSchema`: `skillId` (required, valid ObjectId), `title` (required, max 150), `description` (required, max 1000), `learningObjectives` (optional, max 500), `preferredDifficulty` (optional enum), `preferredDuration` (optional, 15-240), `preferredMode` (optional enum), `preferredSchedule` (optional), `neighborhood` (optional).
   - `updateRequestSchema`: Same fields as create but all optional. Also allows `status` (OPEN/CANCELLED).
3. **`backend/src/controllers/offerController.js`:**
   - `getOffers`: Public. Paginated list of ACTIVE offers with filters: `skillId`, `category` (via populate), `learningMode`, `experienceLevel`, `search`, `page`, `limit`. Populates `skillId` (name, category, difficulty) and `providerId` (name, username, city, averageRating).
   - `getMyOffers`: Protected. Returns all offers for the authenticated provider (all statuses).
   - `getOfferById`: Public. Returns single offer detail with populated skill and provider.
   - `createOffer`: Protected. Validates that `skillId` exists. Enforces unique `(providerId, skillId)`. Sets `providerId` to `req.user._id`.
   - `updateOffer`: Protected. Owner-only (or ADMIN). Updates allowed fields.
   - `deleteOffer`: Protected. Owner-only (or ADMIN). Removes the offer document.
4. **`backend/src/controllers/requestController.js`:**
   - `getRequests`: Public. Paginated list of OPEN requests with filters: `skillId`, `preferredMode`, `status`, `search`, `page`, `limit`. Populates `skillId` and `learnerId`.
   - `getMyRequests`: Protected. Returns all requests for the authenticated learner.
   - `getRequestById`: Public. Returns single request detail with populated skill and learner.
   - `createRequest`: Protected. Validates `skillId` exists. Sets `learnerId` to `req.user._id`.
   - `updateRequest`: Protected. Owner-only (or ADMIN). Updates allowed fields.
   - `deleteRequest`: Protected. Owner-only (or ADMIN). Removes the request document.
5. **`backend/src/routes/offers.js`:**
   - `GET /api/offers` — Public directory.
   - `GET /api/offers/my` — Protected, provider's own offers.
   - `GET /api/offers/:id` — Public detail.
   - `POST /api/offers` — Protected, validated.
   - `PUT /api/offers/:id` — Protected, owner-only, validated.
   - `DELETE /api/offers/:id` — Protected, owner-only.
6. **`backend/src/routes/requests.js`:**
   - `GET /api/requests` — Public directory.
   - `GET /api/requests/my` — Protected, learner's own requests.
   - `GET /api/requests/:id` — Public detail.
   - `POST /api/requests` — Protected, validated.
   - `PUT /api/requests/:id` — Protected, owner-only, validated.
   - `DELETE /api/requests/:id` — Protected, owner-only.
7. **Mount `/api/offers` and `/api/requests` in `backend/src/app.js`.**

## 4. Acceptance Criteria
- [ ] `POST /api/offers` creates an offer linked to the authenticated user and a valid skill.
- [ ] Duplicate `(providerId, skillId)` combination returns HTTP 409.
- [ ] `PUT /api/offers/:id` by a non-owner returns HTTP 403.
- [ ] `GET /api/offers` returns only ACTIVE offers by default with populated skill and provider info.
- [ ] `POST /api/requests` creates a request linked to the authenticated user and a valid skill.
- [ ] `PUT /api/requests/:id` by a non-owner returns HTTP 403.
- [ ] Learners can cancel their own open requests by setting status to CANCELLED.
- [ ] `GET /api/requests` returns only OPEN requests by default with populated skill and learner info.
- [ ] All protected endpoints reject unauthenticated access with HTTP 401.
