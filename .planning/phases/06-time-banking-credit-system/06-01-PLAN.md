# Phase 6 — Plan 06-01: Atomic Credit Ledger Service & Double-Entry Accounting (Wave 1)

## 1. Goal
Implement the core financial accounting service in `backend/src/services/creditService.js` that executes atomic credit transfers, enforces non-negative balance invariants, and logs immutable transaction entries into the `CreditTransaction` collection.

## 2. Deliverables
1. **`backend/src/services/creditService.js`:**
   - `transferSessionCredits(sessionId)`:
     - Fetches session with learner, provider, and skill.
     - Checks if session is already paid/settled to avoid duplicate awards.
     - If marked `isReciprocal`, logs zero-balance barter transaction.
     - Otherwise executes atomic debit from learner and credit to provider using atomic conditional updates or MongoDB transaction sessions.
     - Creates `CreditTransaction` document.
   - `getUserCreditSummary(userId)`:
     - Returns `{ currentBalance, totalEarned, totalSpent, transactionCount }`.
   - `getLedgerTransactions(userId, options)`:
     - Returns paginated transaction list where `senderId === userId` OR `receiverId === userId`.
     - Populates counterparties and session details.
   - `executeAdminAdjustment(adminId, targetUserId, amount, type, description)`.
2. **Offline-Resilient Mode:**
   - Provides deterministic demo balance and mock ledger transactions when database is offline or in test mode.

## 3. Acceptance Criteria
- [ ] Transferring session credits deducts the exact `creditValue` from the learner and adds it to the provider.
- [ ] Cannot deduct credits if learner balance is less than required (solvency guard).
- [ ] Duplicate execution of `transferSessionCredits` for the same session is prevented.
- [ ] Reciprocal swaps log a barter transfer without currency deduction.
- [ ] Every transfer creates a corresponding `CreditTransaction` record.
