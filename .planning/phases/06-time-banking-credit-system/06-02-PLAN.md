# Phase 6 — Plan 06-02: Credit REST API & Session Completion Automation (Wave 2)

## 1. Goal
Expose the credit ledger via Express REST API endpoints in `backend/src/controllers/creditController.js` and `backend/src/routes/credits.js`, and connect session completion in `sessionController.js` to automatically trigger credit settlements.

## 2. Deliverables
1. **`backend/src/validators/creditValidators.js`:**
   - Zod schema for admin adjustments: validates `targetUserId`, `amount` ($> 0$), `type` (`ADMIN_ADJUSTMENT`), and `description`.
2. **`backend/src/controllers/creditController.js`:**
   - `getBalanceSummary`: `GET /api/credits/balance` (Private, returns balance, lifetime stats, and recent activity).
   - `getLedgerHistory`: `GET /api/credits/ledger` (Private, paginated transaction history with filters for `type`: `EARNED`, `SPENT`, `BONUS`, `ALL`).
   - `adminAdjustCredits`: `POST /api/credits/admin-adjust` (Admin only).
3. **`backend/src/routes/credits.js`:**
   - Express router guarded by `protect` (and `authorize('ADMIN')` for adjustments).
4. **Automate Session Completion:**
   - Update `confirmSession` in `backend/src/controllers/sessionController.js`:
     - When session transitions to `COMPLETED`, automatically call `creditService.transferSessionCredits(session._id)`.
5. **Mount in `backend/src/app.js` and register in root discovery (`GET /api`).**

## 3. Acceptance Criteria
- [ ] `GET /api/credits/balance` returns current credit balance and stats for logged-in user.
- [ ] `GET /api/credits/ledger` returns paginated list of transactions.
- [ ] Confirming a session triggers automatic credit transfer and creates transaction records.
- [ ] Admin adjustment endpoint requires `ADMIN` role.
