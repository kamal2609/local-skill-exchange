# Phase 8 — Plan 08-01: Backend Admin API, Moderation & Metrics (Wave 1)

## 1. Goal
Implement the administrative backend suite in `backend/src/controllers/adminController.js` and `backend/src/routes/admin.js`, providing platform metric aggregations, user account management (suspension/reactivation/role change), safety report moderation, and skill category management.

## 2. Deliverables
1. **`backend/src/validators/adminValidators.js`:**
   - `updateUserStatusSchema`: `{ isActive: z.boolean() }`
   - `updateUserRoleSchema`: `{ role: z.enum(['LEARNER', 'PROVIDER', 'ADMIN']) }`
   - `resolveReportSchema`: `{ status: z.enum(['PENDING', 'REVIEWED', 'RESOLVED', 'DISMISSED']), adminNotes: z.string().max(1000).optional() }`
   - `createCategorySchema`: `{ name: z.string().min(2).max(50), description: z.string().max(200).optional(), icon: z.string().optional() }`

2. **`backend/src/controllers/adminController.js`:**
   - `getAdminMetrics`: Aggregated KPIs (totalUsers, activeUsers, totalSkills, activeOffers, openRequests, completedSessions, totalCreditsInCirculation, pendingReportsCount) with offline fallback.
   - `getAdminUsers`: Searchable, filterable, and paginated user list with full profile details.
   - `updateUserStatus`: Toggle `isActive` on a user document (suspend/reinstate).
   - `updateUserRole`: Promote or demote user role.
   - `getAdminReports`: List all safety reports with populate on reporter and reported user, filterable by `status`.
   - `resolveReport`: Update report status to `RESOLVED` or `DISMISSED` with admin audit notes.
   - `createCategory`: Add a new skill category taxonomy entry.

3. **`backend/src/routes/admin.js`:**
   - Mount with `protect` and `authorize('ADMIN')` on all routes.
   - Map routes:
     - `GET /metrics` → `getAdminMetrics`
     - `GET /users` → `getAdminUsers`
     - `PUT /users/:id/status` → `updateUserStatus`
     - `PUT /users/:id/role` → `updateUserRole`
     - `GET /reports` → `getAdminReports`
     - `PUT /reports/:id` → `resolveReport`
     - `POST /categories` → `createCategory`

4. **Integration in `backend/src/app.js`:**
   - Mount at `app.use('/api/admin', adminRoutes);`
   - Add `admin: '/api/admin'` to root discovery endpoint (`GET /api`).

## 3. Acceptance Criteria
- [ ] Non-authenticated requests to `/api/admin/*` return HTTP 401.
- [ ] Authenticated `LEARNER` or `PROVIDER` requests return HTTP 403.
- [ ] Authenticated `ADMIN` requests return HTTP 200 with platform metrics.
- [ ] Toggling user status updates `isActive` and prevents deactivated users from logging in or booking sessions.
- [ ] Updating report status records `adminNotes` and sets status.
- [ ] All database queries include offline demo fallbacks when `mongoose.connection.readyState !== 1`.
