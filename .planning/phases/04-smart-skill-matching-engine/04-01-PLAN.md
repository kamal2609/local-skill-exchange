# Phase 4 — Plan 04-01: Matching Algorithm Service & Scoring Engine (Wave 1)

## 1. Goal
Implement the core mathematical matching algorithm in `backend/src/services/matchingService.js` that evaluates pairwise user compatibility according to the approved 6-tier weighted formula and produces explainable rationales.

## 2. Deliverables
1. **`backend/src/services/matchingService.js`:**
   - `calculateCompatibility(userA, userB, context)`:
     - Calculates $S_{\text{skill}} \in [0, 40]$
     - Calculates $S_{\text{reciprocal}} \in [0, 25]$
     - Calculates $S_{\text{availability}} \in [0, 15]$
     - Calculates $S_{\text{experience}} \in [0, 10]$
     - Calculates $S_{\text{location}} \in [0, 5]$
     - Calculates $S_{\text{language}} \in [0, 5]$
     - Computes total score $S = \sum S_i \in [0, 100]$
     - Generates explainable reasons array (`explanations: string[]`)
   - `findMatchesForUser(userId, options)`:
     - Loads active offers, requests, and availability for `userId`.
     - Queries candidate users (`isActive: true`, excluding `userId`).
     - Evaluates compatibility for each candidate.
     - Filters by minimum score threshold (default: 20%).
     - Sorts descending by score and reciprocal flag.
   - `findReciprocalMatches(userId)`:
     - Specifically filters for candidate pairs where reciprocal barter condition is met ($S_{\text{reciprocal}} = 25$).
2. **Offline-Resilient Mode:**
   - If database is disconnected or running in test mode, the service calculates scores accurately using in-memory demo profiles so tests and offline demonstrations run without interruption.

## 3. Acceptance Criteria
- [ ] Reciprocal pairing returns the 25-point bonus.
- [ ] Non-reciprocal pairing returns 0 for the reciprocal component.
- [ ] Direct skill match awards full 40 points.
- [ ] Shared languages award 5 points; disjoint languages award 0 points.
- [ ] Proximity calculation awards 5 points for matching neighborhood and 3 points for same city.
- [ ] Total score never exceeds 100 or drops below 0.
- [ ] Every match object contains a populated `breakdown` object and human-readable `explanations` array.
