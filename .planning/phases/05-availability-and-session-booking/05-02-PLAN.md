# Phase 5 — Plan 05-02: Session Booking Engine & State Machine (Wave 2)

## 1. Goal
Implement the booking engine, conflict detection, and session state machine in `backend/src/controllers/sessionController.js` and `backend/src/routes/sessions.js` with credit valuation checks and dual-confirmation flows.

## 2. Deliverables
1. **`backend/src/validators/sessionValidators.js`:**
   - Zod schema for session creation: validates `providerId`, `skillId`, `bookingDate`, `startTime`, `endTime`, `duration` ($15-240$ min), `notes`, `meetingLink`.
   - Zod schema for status update: validates `status` $\in ['ACCEPTED', 'REJECTED', 'CANCELLED']` and optional cancellation reason.
2. **`backend/src/controllers/sessionController.js`:**
   - `createSession`: `POST /api/sessions`
     - Validates learner cannot book with self.
     - Calculates credit value ($\text{duration} / 60$).
     - Solvency check: verifies learner has sufficient balance or is an approved reciprocal swap.
     - Conflict check: queries both learner and provider for conflicting sessions on the given date and overlapping time interval.
     - Creates session with default status `'REQUESTED'`.
   - `getSessions`: `GET /api/sessions`
     - Returns sessions where `learnerId === req.user._id` OR `providerId === req.user._id`.
     - Supports filters: `status`, `role` (`asLearner`, `asProvider`, `all`).
     - Populates learner, provider, and skill details.
   - `getSessionById`: `GET /api/sessions/:id`
     - Retrieves full session details; enforces participant authorization.
   - `updateSessionStatus`: `PUT /api/sessions/:id/status`
     - Enforces state transition rules: only provider can ACCEPT or REJECT; either party can CANCEL before completion.
     - When ACCEPTED, status transitions to `SCHEDULED`.
   - `confirmSession`: `POST /api/sessions/:id/confirm`
     - Records `learnerConfirmed: true` or `providerConfirmed: true`.
     - When confirmed, sets status to `COMPLETED` and sets stage for Phase 6 credit transfer.
3. **`backend/src/routes/sessions.js`:**
   - Express router guarded by `protect`.
4. **Mount in `backend/src/app.js` and register in root discovery endpoint (`GET /api`).**

## 3. Acceptance Criteria
- [ ] Self-booking is blocked with HTTP 400.
- [ ] Overlapping booking requests are rejected with a double-booking conflict error (HTTP 409).
- [ ] Learner with insufficient credit balance is blocked (HTTP 400).
- [ ] Provider accepting a session updates status to `SCHEDULED`.
- [ ] Confirmation by participants updates `learnerConfirmed` / `providerConfirmed` and marks status `COMPLETED`.
- [ ] API endpoints are fully protected by JWT authentication.
