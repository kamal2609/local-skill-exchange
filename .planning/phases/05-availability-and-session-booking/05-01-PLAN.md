# Phase 5 — Plan 05-01: Availability Management API & Weekly Scheduler (Wave 1)

## 1. Goal
Implement the backend availability management endpoints in `backend/src/controllers/availabilityController.js` and `backend/src/routes/availability.js` with Zod validation to allow users to configure recurring weekly schedules, preferred durations, timezone, and learning format.

## 2. Deliverables
1. **`backend/src/validators/availabilityValidators.js`:**
   - Zod schema for single slot and bulk weekly schedule array.
   - Validates `dayOfWeek` ($0-6$), `startTime` (`HH:mm`), `endTime` (`HH:mm`), `startTime < endTime`, `learningMode` (`ONLINE`, `IN_PERSON`, `HYBRID`), and `preferredDuration` ($15-240$).
2. **`backend/src/controllers/availabilityController.js`:**
   - `getMyAvailability`: `GET /api/availability/my` (returns all active weekly slots sorted by day of week and start time).
   - `updateMyAvailability`: `PUT /api/availability/my` (atomic bulk replacement of user's weekly availability slots with duplicate overlap checks).
   - `getUserAvailability`: `GET /api/availability/user/:userId` (public view for booking calendar).
   - `createSlot`: `POST /api/availability` (creates single slot with overlap prevention).
   - `deleteSlot`: `DELETE /api/availability/:id` (removes slot with ownership validation).
3. **`backend/src/routes/availability.js`:**
   - Express router mounting the above endpoints with `protect` where appropriate.
4. **Mount in `backend/src/app.js` and register in root discovery endpoint (`GET /api`).**

## 3. Acceptance Criteria
- [ ] Unauthenticated requests to `/api/availability/my` return HTTP 401.
- [ ] Valid bulk PUT to `/api/availability/my` replaces the user's weekly slots cleanly.
- [ ] Validation rejects invalid times (e.g. `startTime: '18:00', endTime: '17:00'` or invalid military format).
- [ ] `GET /api/availability/user/:userId` returns active slots for candidate providers.
- [ ] Deleting a slot verifies that the authenticated user owns that slot.
