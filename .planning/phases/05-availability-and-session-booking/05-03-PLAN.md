# Phase 5 — Plan 05-03: Frontend Availability Scheduler & Sessions Dashboard UI (Wave 3)

## 1. Goal
Build the frontend user interfaces for managing weekly availability, initiating session bookings from offers and smart matches, and managing scheduled sessions on a dedicated `/sessions` dashboard.

## 2. Deliverables
1. **Weekly Availability Scheduler Component:**
   - Visual 7-day schedule editor (`frontend/src/components/availability/AvailabilityScheduler.tsx` or integrated into Profile / Sessions).
   - Add/remove time slots per weekday (Sunday through Saturday).
   - Mode toggles (`ONLINE`, `IN_PERSON`, `HYBRID`) and timezone indicator.
   - Bulk save button calling `PUT /api/availability/my`.
2. **Session Booking Modal / Page:**
   - `frontend/src/components/sessions/BookingModal.tsx`:
     - Select date from date picker.
     - Automatically renders available hours based on provider's active weekly slots.
     - Duration selector (30m, 60m, 90m, 120m) with real-time credit calculation ($0.5$, $1.0$, $1.5$, $2.0$ credits).
     - Notes and online meeting link inputs.
     - Direct triggers from `OfferDetailPage.tsx`, `MatchesPage.tsx`, and `PublicProfilePage.tsx`.
3. **Sessions Management Dashboard (`frontend/src/pages/SessionsPage.tsx` at `/sessions`):**
   - Protected route.
   - Status Tabs:
     - "Upcoming & Scheduled"
     - "Pending Requests" (with prominent "Accept" and "Decline" actions for providers)
     - "Completed Sessions" (with completion badge and review prompt)
     - "Cancelled"
   - Session Card Components:
     - Counterparty Avatar, Name, and Role.
     - Skill name, category badge, and credit cost.
     - Date, formatted time range, and duration.
     - Action buttons: "Accept Request", "Decline", "Join Online Meeting", "Confirm Session Completion", "Cancel Session".
4. **Navigation & Route Integration:**
   - Update `frontend/src/components/Navbar.tsx`: Add "Sessions" link with active session counter.
   - Update `frontend/src/App.tsx`: Mount `/sessions` guarded by `<ProtectedRoute>`.
5. **Verification:**
   - Node test script (`backend/test/phase5Verification.js`) verifying availability CRUD, booking conflicts, state transitions, and dual confirmations.
   - Frontend production build (`tsc -b && vite build`) passing with zero errors.

## 3. Acceptance Criteria
- [ ] Users can edit and save recurring weekly availability slots on the frontend.
- [ ] Learners can book available slots from an offer or partner card.
- [ ] Real-time credit calculation is displayed during booking.
- [ ] Providers can accept or decline pending booking requests from `/sessions`.
- [ ] Confirming a session updates its visual status to `COMPLETED`.
- [ ] Navbar displays the "Sessions" link for logged-in users.
- [ ] Production build compiles with zero TypeScript or bundling errors.
